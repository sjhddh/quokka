# Quokka Roadmap

> Converged from 7-perspective panel debate: Product Strategy, Growth, Architecture, UX, Open Source, Monetization, Tech Debt.

---

## Key Decisions

| Debate | Verdict |
|--------|---------|
| Companion server | **Kill as requirement.** Extension-only for 80% use cases. Companion = opt-in power mode. |
| Monorepo 9 packages | **Collapse to 3.** `extension`, `companion`, `shared`. 9 packages at 4 commits = premature. |
| NL "Do" mode | **Shelve.** Feature-flag, hide from UI. Bring back v0.5 after core loop proven. |
| CLI | **Defer to v0.5.** Target users are non-technical. Build on demand signal. |
| Recipe marketplace | **Never (for now).** Shareable links → GitHub directory → marketplace only if revenue demands. |

---

## Phase 1: Foundation (v0.3, ~4 weeks)

### Build
- [ ] **Extension-only runtime** — record/replay without companion server or terminal
- [ ] **Collapse monorepo** to 3 packages: `extension`, `companion`, `shared`
- [ ] **Floating pill UI** replacing popup (record/play/stop)
- [ ] **One-click recipe sharing** — `.quokka.json` export + URL scheme import
- [ ] **Graceful failure** — pause on selector miss, highlight element, Retry/Skip/Fix
- [ ] **Recipe schema v1** — signed JSON, no eval, allowlisted step types
- [ ] Companion becomes optional (headless/filesystem only)

### Do NOT Build
- NL "Do" mode (feature-flagged, hidden)
- CLI, gallery, marketplace, cloud sync
- Firefox/Safari, hooks/plugins, conditional logic

### Ship Criteria
> A non-technical user installs from Chrome Web Store, records a workflow, replays it, shares it with a colleague — **without opening a terminal.**

## Phase 2: Growth (v0.5, ~3 months)

### Build
- [ ] **HN launch** — 20 starter recipes, GIF demos, landing page
- [ ] **5 vertical starter packs** (HR, sales, support, social media, data entry)
- [ ] **`community-recipes/`** GitHub directory accepting PRs
- [ ] **Fallback selectors** — aria-label → text content → nth-child (3-deep chain)
- [ ] **Visual timeline editor** — reorder, delete, edit selectors
- [ ] **CONTRIBUTING.md** + issue templates + 10 good-first-issues
- [ ] **BYOK LLM setting** in extension (prep for NL features)
- [ ] CLI package (if demand signal exists)

### Do NOT Build
- Hosted LLM, paid tier, cloud sync, accounts
- NL "Do" mode in UI, scheduled runs, Firefox/Safari

### Ship Criteria
> Recipe link sharing converts >10% of recipients to installs. 50+ community-contributed recipes.

---

## Phase 3: Platform (v1.0, ~6 months)

### Build
- [ ] **NL "Do" mode** re-enabled (BYOK only)
- [ ] **Scheduled runs** via companion (cron-style)
- [ ] **Conditional logic** — if/else on element presence
- [ ] **Pro tier ($9/mo)** — hosted LLM, cloud recipe sync, scheduled runs
- [ ] **Self-healing selectors** — LLM fallback when static selectors fail
- [ ] **Firefox support** via WebExtension polyfill
- [ ] Getting Started guide + video walkthrough

### Do NOT Build
- Enterprise tier, Safari, marketplace, mobile

### Ship Criteria
> 100+ WAU running scheduled recipes. Pro conversion >2% of active users.

---

## Top 5 Priorities (Ranked)

1. **Extension-only replay** — everything is blocked by this. Terminal = 90% user loss.
2. **Collapse monorepo to 3 packages** — do first or every change costs 3x.
3. **Shareable recipe links with install CTA** — the entire growth engine.
4. **Floating pill UI** — the popup is a dead end. The pill IS the product surface.
5. **Fallback selectors** — without selector resilience, "Run forever" is a lie.

---

## Anti-Goals (What Quokka Is NOT)

- **Not a testing framework.** Don't chase Playwright/Cypress users.
- **Not a cloud platform.** No hosted execution, no dashboards.
- **Not an AI product.** LLM is a convenience feature, not the pitch.
- **Not enterprise software.** Until revenue covers a second person.
